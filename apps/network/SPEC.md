# Spec: Migrate the network cluster from Terranetes to Crossplane

## Objective

Replace **Terranetes** (Appvia Terraform-operator) with **Crossplane** as the in-cluster
IaC engine for the `network` vind cluster, mirroring what PR #989 did for the `secret`
cluster. In the network cluster Terranetes manages exactly **one** thing: the entire
**tailnet policy file** (`tailscale_acl`) via the OpenTofu module
`apps/network/src/tailscale-config`. After this change the tailnet policy is reconciled by
[`millstonehq/provider-upjet-tailscale`](https://github.com/millstonehq/provider-upjet-tailscale)
through a Crossplane `ACL` managed resource.

Secondarily, replace the vendored single-node `mongo` Helm chart with the
[**Percona Server for MongoDB Operator**](https://github.com/percona/percona-server-mongodb-operator).
MongoDB currently cannot start because its credentials were never seeded; the operator
solves this by **generating** the credentials itself. A custom `omada` application user is
declared on the `PerconaServerMongoDB` CR, and Omada connects using the operator-**generated
connection string** (see the [connection-secret structure](https://docs.percona.com/percona-operator-for-mongodb/connection-secrets.html#secret-structure)).
Because Percona owns credential generation in-cluster, **no OpenBao involvement is needed for
MongoDB** and the network cluster stays strictly read-only on OpenBao.

**User:** the repo maintainer operating the home-lab clusters. **Success looks like:** a
freshly recreated network cluster where Crossplane owns the tailnet policy, Omada comes up
against a MongoDB whose credentials were generated by ESO, and Terranetes is fully gone —
brought up with the existing `moon run network:*` flow and applied directly to a live
cluster.

### Non-goals
- No change to Omada, the apiserver-proxy, cert-manager, external-dns, the ProxyGroup, or
  the tailnet ACL **content** (the policy is translated verbatim, not redesigned).
- No migration of any other cluster (e.g. `network-controllers-prod`) off Terranetes; the
  shared `platform-terranetes` bundle stays for its other consumers, it is just no longer
  targeted at the network cluster.
- No change to how the `secret` cluster authenticates to its own local OpenBao.

## Tech Stack

- **Crossplane** core `2.3.3` (vendored Helm chart, reused from the secret migration).
- **Provider:** `ghcr.io/millstonehq/provider-upjet-tailscale`, pinned to
  `v0.1.0` **by image digest** (arm64-native; wraps `tailscale/tailscale` TF provider
  `0.22.0`). It is the only published version and has no git tags/releases — pin the digest.
- **Percona Server for MongoDB Operator** — pin operator chart/image **`1.23.0`** (first
  release with native **arm64** for all images; earlier operators are amd64-only). CRDs are
  split into a separate chart (`psmdb-operator-crds`) since 1.22. DB image pinned to the
  **latest stable, `percona/percona-server-mongodb:8.0.26-11`**. Percona's build may not carry
  the community MongoDB SERVER-121912 kernel guard that broke `mongo:8.0.26` on OrbStack/vind —
  so we try latest stable first and **validate it actually starts on the vind node during
  development** (see Testing). Documented fallback if it refuses to start: pin
  `7.0.37-20` (the 7.0 series predates the guard), mirroring the old `mongo:8.0.4` workaround.
- **External Secrets Operator (ESO)** — already deployed; used with a **Kubernetes**
  `SecretStore` to copy/transform the Percona-generated connection string into the Secret
  Omada consumes (no OpenBao path for MongoDB).
- **OpenBao** `2.5.x` on the secret cluster, reached over the tailnet at
  `https://openbao.secret.vgijssel.nl`. Root token available as `VAULT_TOKEN` in `.env`.
- **Fleet** GitOps bundles; **vind** (vcluster docker driver); **Moon** tasks; arm64.

### Tailscale authentication — the load-bearing constraint
The provider's README advertises OAuth, but the implementation (verified at ref
`b8fd21e` **and** `main` HEAD) only ever sets the Terraform provider's `api_key` from the
credential secret — it declares `oauth_client_id`/`oauth_client_secret` constants but never
reads them. Tailscale also requires OAuth secrets to be exchanged at `/oauth/token` (they
are not usable as a raw bearer). **Therefore auth is a static Tailscale API access token**
(`tskey-api-…`) with the `policy_file` write scope, stored in OpenBao at
`kv/network-tailscale-crossplane` (key `api_key`) and synced by ESO into the Secret the
`ProviderConfig` reads. Cost: Tailscale API keys expire (≤90 days) → periodic reseed.

## Commands

```bash
# Lifecycle (Moon; run from repo root)
moon run network:start        # create/reconnect the vind cluster "network"
moon run network:apply        # install Fleet + apply all bundles (Crossplane, no Terranetes)
moon run network:bootstrap    # seed operator-oauth + the Tailscale api_key into OpenBao (uses VAULT_TOKEN from .env)
moon run network:stop         # delete the vind cluster

# One-time seed of the Crossplane Tailscale API key (folded into network:bootstrap):
#   create a Tailscale API access token (policy_file write) in the admin console, then:
VAULT_ADDR=https://openbao.secret.vgijssel.nl VAULT_TOKEN=<root-from-.env> \
  bao kv put kv/network-tailscale-crossplane api_key=tskey-api-xxxx

# Quality gates
trunk fmt
trunk check

# Verification
kubectl --context vcluster-docker_network get providers.pkg.crossplane.io
kubectl --context vcluster-docker_network get acl.acl.tailscale.upbound.io -o wide   # SYNCED=True READY=True
kubectl --context vcluster-docker_network -n mongodb get psmdb                        # PerconaServerMongoDB ready
kubectl --context vcluster-docker_network -n mongodb get secret mongodb-custom-user-secret-conn-str
kubectl --context vcluster-docker_network -n omada get secret mongodb-uri             # ESO-materialized
kubectl --context vcluster-docker_network -n omada get pods                          # Omada Running
```

`network:configure` (the Terranetes out-of-band first apply) is **removed** — see Boundaries.

## Code Style

Match the secret cluster's Crossplane manifests exactly: each file is a single-purpose YAML
with a top-of-file comment block explaining *why* (invariants, gotchas), `deletionPolicy:
Orphan` on every managed resource, and `providerConfigRef` by name. Example (the ACL MR):

```yaml
# The tailnet policy file, managed by Crossplane (provider-upjet-tailscale) — the
# Crossplane replacement for the terranetes tailscale_acl. deletionPolicy: Orphan so
# deleting this MR (Fleet GC, handoff) NEVER destroys the live tailnet policy.
apiVersion: acl.tailscale.upbound.io/v1alpha1
kind: ACL
metadata:
  name: tailnet
spec:
  deletionPolicy: Orphan
  providerConfigRef:
    name: tailscale
  forProvider:
    acl: |
      {
        "autoApprovers": { "services": { "svc:omada-network": ["tag:network-k8s"], ... } },
        "groups": { "group:admin": ["mvgijssel@github"] },
        "tagOwners": { ... },
        "acls": [ ... ],
        "grants": [ ... ],
      }
```

- Fleet `fleet.yaml`: always declare `targetCustomizations` selecting
  `cluster.vgijssel.nl/name: network` (a missing target deploys everywhere and would clobber
  the secret cluster — see the existing `config/fleet.yaml` note).
- Providers pinned by tag **and** digest. Provider SA name pinned via a
  `DeploymentRuntimeConfig` (stable name `provider-tailscale`).
- Shell scripts: `set -euo pipefail`, idempotent, load `.env` with `set -a; . .env; set +a`,
  read secrets only into shell variables (never to disk/git).

## Testing Strategy

No unit-test framework — this is declarative infra validated by live reconciliation on a
recreated cluster (the change is applied directly, per the request).

- **Lint:** `trunk fmt` + `trunk check` (yamllint, shellcheck) must pass.
- **Provider health:** `Provider` `INSTALLED=True HEALTHY=True`; `ProviderConfig` accepted.
- **ACL reconcile:** the `ACL` MR reaches `SYNCED=True READY=True`; the live tailnet policy
  (admin console / `tailscale` API) matches the authored HuJSON. Verify create/adopt
  semantics of the upjet `ACL` resource — confirm it re-asserts (does not wipe) the policy,
  since content is unchanged from the current live policy.
- **MongoDB (Percona):** deploy PSMDB **`8.0.26-11`** first and confirm all **3** `rs0`
  members actually reach `Running`/`ready` on the vind/OrbStack node (this is the explicit
  kernel-guard validation — check pod logs for a SERVER-121912 / kernel-version refusal; if
  seen, fall back to `7.0.37-20` and re-validate). The operator generates
  `mongodb-custom-user-secret` + `mongodb-custom-user-secret-conn-str` for the `omada` user;
  ESO materializes the `mongodb-uri` Secret in the `omada` namespace from that connection
  string; the replica set elects a primary and Omada authenticates against the `omada` database.
- **End-to-end:** `moon run network:stop && network:start && network:apply && network:bootstrap`
  brings the cluster up clean with Omada `Running` and no Terranetes objects present
  (`kubectl get crds | grep terraform.appvia.io` → empty on the network cluster).
- **Secret-cluster regression:** after deleting `role-network-terranetes`, the network
  cluster's ESO still reads `kv/*` via `network-eso`; the new `network-mongodb` role permits
  only `kv/mongodb` writes.

## Boundaries

**Always**
- Pin the provider by digest; keep `deletionPolicy: Orphan` on every managed resource.
- Keep every network bundle `targetCustomizations`-scoped to `cluster.vgijssel.nl/name: network`.
- Run `trunk fmt` + `trunk check` before considering a change done.
- Preserve the tailnet ACL content verbatim when translating `main.tf` → the `ACL` HuJSON.

**Ask first**
- Removing/altering the shared `platform-terranetes` bundle (other clusters may consume it);
  here we only stop targeting it at network.
- Any change to the ACL policy content, tags, or grants.
- Adding dependencies or new vendored charts/images.

**Never**
- Commit secrets, the root token, or any `tskey-*` value to git.
- `kubectl delete` the `ACL` managed resource without `Orphan` in place (would risk the live
  tailnet policy / lockout) — mirrors the Terranetes `orphan` invariant.
- Remove the secret cluster's `network-eso` role or its read path.
- Deploy a network bundle without a `targetCustomizations` selector.

## Success Criteria

1. Terranetes is absent from the network cluster: no `terraform.appvia.io` CRs/CRDs, no
   `tailscale-config` OpenTofu module, no `configure` task; the 3 Terranetes files and the TF
   module are deleted.
2. Crossplane core + `provider-upjet-tailscale` are installed and healthy on the network
   cluster; a `ProviderConfig` named `tailscale` authenticates via the ESO-synced `api_key`.
3. An `ACL` managed resource is `SYNCED=True READY=True` and owns the tailnet policy
   (content identical to today's), with `deletionPolicy: Orphan`.
4. The Percona operator runs the MongoDB cluster on arm64, generates the `omada` user's
   credentials + connection string, and Omada runs against it on a freshly recreated
   cluster — with no `kv/mongodb` and no OpenBao write access on the network side.
5. `apps/secret` no longer contains `role-network-terranetes`, and the network cluster gains
   **no** new OpenBao privileges (stays read-only).
6. `moon run network:start → apply → bootstrap` brings the cluster up end-to-end and the
   change is applied directly to a live, recreated cluster.

## Open Questions

1. **upjet `ACL` create/adopt semantics** — confirm on first apply that the `ACL` resource
   re-asserts the authored policy rather than resetting the tailnet (content is unchanged, so
   risk is low, but verify against a live apply before trusting it). If needed, adopt the
   existing policy via `crossplane.io/external-name`.
2. **Omada ⇄ Percona connection string** — verify against the live operator that the
   custom-user connection-string secret (`mongodb-custom-user-secret-conn-str`) exists with the
   expected key(s) (e.g. `omada_rs0_connectionString` / `…Srv`) and that Omada accepts it
   verbatim. If Omada requires the `omada` database in the URI path (the old URI used
   `…/omada?authSource=admin`), the ESO `ExternalSecret` template appends it. Confirm the exact
   key name and whether the DB path is needed at implementation time.
3. **PSMDB image validation** — pin latest stable `8.0.26-11` and confirm the 3-member `rs0`
   starts cleanly on the vind/OrbStack node (Percona's build likely lacks the community
   SERVER-121912 kernel guard). Fall back to `7.0.37-20` only if a member refuses to start.
4. **Tailscale API key rotation** — accept ≤90-day manual reseed of
   `kv/network-tailscale-crossplane#api_key`, or should a rotation reminder/mechanism be added
   later?
